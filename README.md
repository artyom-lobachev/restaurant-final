# Java lab 3. Лобачев Артём 24КНТ-3.

## Вариант 3:
**Многопоточная система работы ресторана (официанты + кухня)**

Реализовать модель работы ресторана, где официанты и повара работают параллельно, синхронизируя доступ к очереди заказов.

### Состав системы (по условию)
- Клиенты — периодически генерируют новые заказы.
- Официанты (потоки) — принимают заказы и доставляют готовые блюда. 
- Кухня — пул потоков (ExecutorService) из нескольких поваров.
- Очередь заказов — BlockingQueue.

### Требования
**Официант** должен: принять заказ → поместить в очередь кухни → дождаться готовности → отнести клиенту.  
**Кухня**: каждый заказ готовит один повар из пула, время готовки зависит от блюда, готовность возвращается официанту.  
**Многопоточность**: BlockingQueue + потоки официантов + ExecutorService поваров; без гонок при доступе к очередям, передаче блюд и логировании.  
**Логистика**: учитывается перегрузка кухни, накопление заказов и ожидание освобождения повара.  
**Критерии**: корректная многопоточность без deadlock’ов, FIFO-порядок обработки из очереди, реалистичное моделирование.

## Файлы

- `src/restaurant/Main.java` — запуск симуляции ресторана:
  - создание очереди кухни `BlockingQueue`;
  - запуск потоков официантов, генератора клиентов, диспетчера кухни и монитора;
  - корректная остановка всех потоков.

- `src/restaurant/Core.java` — базовые сущности и конфигурация:
  - `Config` (настройки нагрузки, длительность 30 секунд);
  - `DishType` (типы блюд и задержки готовки);
  - `Order`, `Meal` (заказ и готовое блюдо).

- `src/restaurant/Observability.java` — наблюдаемость и статистика:
  - `EventLogger` (отдельный поток логирования, вывод в виде таблицы);
  - `StatsCollector` (сбор метрик: ожидание в очереди, время готовки, сколько приготовил каждый повар);
  - `Monitor` (периодический вывод состояния: `очередь_кухни`, `свободные_повара`, агрегаты).

- `src/restaurant/Staff.java` — работа официантов и клиентов:
  - `Waiter` (поток официанта): принимает заказы и доставляет готовые блюда;
  - готовность блюда приходит обратно через `CompletableFuture` в личную очередь официанта (без блокировки при ожидании);
  - `ClientGenerator` (генерирует клиентов/заказы с задержками).

- `src/restaurant/Kitchen.java` — кухня:
  - `KitchenDispatcher` — забирает заказы из `kitchenQueue` и отправляет в пул поваров;
  - `CookTask` — готовит блюдо (sleep) и завершает `CompletableFuture` заказа;
  - `Semaphore` ограничивает одновременную готовку числом поваров (модель “ждём свободного повара”);
  - `NamedThreadFactory` — человекочитаемые имена потоков (`Повар_1`, `Официант_1` и т.д.).

## Дополнительные функции

По сравнению с базовым заданием реализовано:

- **Визуальный консольный вывод**: лог печатается в виде таблицы с фиксированными колонками и именами потоков (удобно доказывает многопоточность).
- **Мониторинг и метрики**: периодический статус + статистика по очереди и готовке (среднее/максимум) и распределение заказов по поварам.
- **Более реалистичная модель официанта**: официант не “зависает” на ожидании готовки; готовые блюда приходят отдельным каналом (`CompletableFuture.thenAccept(...)`), параллельно можно принимать новые заказы.
- **Корректное завершение**: аккуратная остановка генератора, официантов, диспетчера и пула поваров без deadlock’ов.
